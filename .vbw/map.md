# Codebase map

## Stack and commands
- Bash-first installer plus Claude Code hooks (`hooks/{global,lib,project}`, `setup.sh`, `tests/`). Python 3 only for `scripts/analyze-*.py`. No package manager, no CI (`.github` absent). No runtime server. Runtime deps: jq, bash, python3, codebase-memory-mcp, Claude Code `settings.json`.
- Version 1.12.0 in `VERSION` and `version.txt` (keep in sync). `CHECKSUMS.sha256` is generated by `scripts/generate-checksums.sh`.
- Install: `./setup.sh` (writes to `~/.claude`; see `README.md`, `docs/setup-guide.md`). Build: none.
- Test all: `make test`. Test one: `bash tests/<name>.sh`.
- Analysis: `make measure DAYS=30 [MODEL=..]` (read-only, local transcripts).
- Release: `scripts/bump-version.sh` (do not run unless asked).
- Lint: no target. Suggested: `shellcheck -S warning $(git ls-files '*.sh')`. It currently exits non-zero (e.g. SC1090 at `tests/test-version-stamp.sh:117`, also SC1102 and SC1125); findings are untriaged. Extensionless hook files are not covered by that glob.

## Conventions
- No `.editorconfig`, `.shellcheckrc` or CI. Rules are prose in `CLAUDE.md` and `CONTRIBUTING.md`.
- Hook file style (e.g. `hooks/project/session-gate.sh` lines 1-14):
  - `#!/bin/bash`.
  - Line 2 is `name.sh — Event:Matcher hook (purpose)`.
  - The header lists BLOCKING or non-blocking, Install (cp + chmod +x) and the `settings.json` snippet.
  - Libs add a WHY THIS EXISTS block. Section markers are `# --- Name ---`.
- Input: `INPUT=$(cat)` first. Extract tool_name with grep/sed, python3 fallback. Deps limited to jq and python3.
- Errors: exit 2 blocks, with the message to stderr via `cat >&2 <<EOF`. Exit 0 allows. Fail open on parse failure or missing CMM registration. Most hooks omit `set -e`. Exceptions: `context-mode-hook-dispatch.sh` uses `set -euo pipefail`, `agent-override-generate.sh` uses `set -uo pipefail`. Libs tolerate `set -u` callers via `${var:-}`.
- Use the shared libs, never re-roll their logic (`tests/test-hooks-use-shared-lib.sh` enforces this). CMM registration is detected by probing the `mcpServers.codebase-memory-mcp` key, never by substring match.
- Agent-tool prompts must reference CMM tools or `agent-cmm-gate.sh` rejects them.
- Process:
  - Commits are `{type}({scope}): {description}`, one atomic commit per task, never amend. Follow the CLAUDE.md superset of types (feat, fix, test, refactor, perf, docs, style, chore); CONTRIBUTING.md lists fewer.
  - Branches: `feature/*` off `develop`, PR to `develop`, then PR to `main` with a version bump and a `vX.Y.Z` tag.
  - Do not run `scripts/bump-version.sh` or `git push` unless asked. Never commit secrets.
  - PRs touching `hooks/`, `setup.sh`, `rules/` or `agents/` need 2-4 read-only Opus QA rounds, each posted as a PR comment. Fixes go in `fix(scope): address QA round N` commits. Docs-only PRs skip QA.

## Tests
- Plain bash, no bats or shunit2 (bats is installed but unused). About 60 `tests/test-*.sh` files, about 12.5k lines. Each is self-contained: header with `Usage:` and `Exit:`, `set -euo pipefail`, local `_pass`/`_fail` counters, `PASS:`/`FAIL:` lines, exit 1 on failure. See `tests/test-cwd-guard.sh`.
- Setup: `mktemp -d /tmp/cmm-*-XXXXXX`, `git init`, an empty commit, copy the hook in, pipe JSON, assert the exit code. Some tests copy the hook without `lib/` to force the fallback path. About 10 are static grep checks with no mktemp (e.g. `test-agent-gate-blocking`, `test-hooks-use-shared-lib`, `test-phase-49-agent-sync`).
- No shared helper lib: each test redefines `_pass`, `_fail`, `_run`. Fixtures: `tests/fixtures/skill-compliance/` (agent1.jsonl, agent2.jsonl). `tests/setup-test-monorepo.sh` builds a monorepo.
- Naming: `test-<hook-or-feature>.sh`, plus legacy `test-phase-NN-*.sh` (45-66, installer regression tests).
- `make test` runs them serially, hides output and prints PASS/FAIL per file. It errors on an empty glob. It takes about 2m41s, which is slow; the cause was not investigated.
- Last run: 55 PASS, 1 FAIL (`tests/test-cmm-nudge-blocking.sh`). Run alone it passes 21/21. Likely shared /tmp state; the cause is unconfirmed (medium confidence).
- Gaps (name-reference counts only, so candidates):
  - 0 mentions: `hooks/global/reindex-after-edit.sh`, `hooks/lib/is-cmm-ext.sh`, `scripts/bump-version.sh`.
  - 1 mention: `hooks/lib/cmm-registered.sh`, `hooks/project/cmm-sentinel-writer.sh`, `hooks/global/user-prompt-submit-skill-nudge.sh`, `scripts/generate-checksums.sh`, `scripts/analyze-enforcement.py`, `scripts/analyze-skill-compliance.sh`.
  - Thin: `cwd-guard`, `index-root-gate` and `webfetch-nudge` have only 2 mentions each.
  - The Python analyzers have no pytest.
- Options (recommend A, then B, then C):

  - B: Add tests for the zero-coverage scripts, starting with `reindex-after-edit` and `bump-version` in a temp repo, plus a stale-sentinel and concurrency test for `session-gate`.

## Risks
- `setup.sh` is a 3510-line monolith that mutates user `settings.json` (62 refs) and does rm/sed/jq edits. It is the highest-risk file. Validate changes with `tests/test-phase-*-bundle-install.sh`. Split into sourced modules only if you touch it often.
- Gate hooks can wedge a whole Claude session, because exit 2 blocks tool calls. The most complex ones are `hooks/project/agent-override-generate.sh` (599 lines), `ctx-execute-enforcer.sh` (535), `ctx-execute-cmm-nudge.sh` (474), `ctx-payload-guard.sh` (434) and `hooks/global/cmm-grep-nudge.sh` (431).
- Global /tmp state (sentinels and per-project counters) is racy across concurrent sessions and stale across reboots and worktrees. Changing `hooks/lib/project-root.sh` shifts every gate (the monorepo fix was phase 16). Confidence medium-high; semantics not fully read.
- Generated files, do not hand-edit:
  - `CHECKSUMS.sha256` covers `hooks/`, `rules/`, `agents/`, `setup.sh` and `tests/`. Tests such as `test-phase-49-agent-sync.sh`, 62 and 63 hash-check it, so regenerate after any edit there.
  - Target-project `.claude/agents/vbw-*.md` are generated from the upstream VBW source plus the `agents/vbw-*.md` deltas. Edit only the deltas.
  - `.vbw-planning/` and `.vbw/` are VBW-managed.
- Unversioned external coupling: the upstream VBW tree (`hooks/lib/vbw-source.sh`, 217 lines), plus Context Mode and CMM tool names and hook payload shapes. Upstream drift breaks the agent-override merge silently, because hooks fail open.
- Process cost: the Opus QA cycle and the version bump are manual, and there is no CI.
