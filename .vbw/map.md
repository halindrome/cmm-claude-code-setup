## Stack and commands

- Pure Bash hooks (`#!/bin/bash`) plus the `setup.sh` installer. Small Python 3 scripts in `scripts/analyze-*.py`. `jq` for JSON. No package manager, no build step, no `package.json`.
- Platforms: macOS, Linux, WSL.
- Version: `VERSION` (1.12.0), `version.txt`, `CHECKSUMS.sha256` (generated by `scripts/generate-checksums.sh`), `scripts/bump-version.sh`.
- Install: `./setup.sh [--global|--project|--all] [--force] [--dry-run] [--skip-mcp-check] [--verify]`. It registers hooks in `~/.claude/settings.json` or `.claude/settings.json`. Run `--dry-run` first.
- Test: `make test` runs every `tests/test-*.sh` (about 3.5 min, serial). Re-run one with `bash tests/<name>.sh`. `make measure [DAYS= MODEL=]` does read-only transcript analysis.
- Lint: none (no Makefile target, no CI, `.github` absent). Ad hoc: `shellcheck -S warning $(find hooks -name '*.sh') setup.sh` (13 files warn). In zsh, `hooks/*.sh` fails because the hooks are in subdirs.
- CMM project: `Users-ahby-Sources-ccs-vbw2` (3674 nodes, 261 files). Query wrapper: `bash /Users/ahby/Sources/ccs-vbw2/.claude/hooks/cmm-query.sh <tool> '<json>'`. Tools: `search_graph`, `get_code_snippet`, `trace_path`, `search_code`, `get_architecture`, `index_repository`.

## Structure

- Bash hook-enforcement stack, not an app. Install-time entry is `setup.sh` (3525 lines, `main` at L3482). It calls `parse_args`, `check_prerequisites`, `install_global`, `install_project`, `merge_settings_json`, `merge_context_mode_hooks`, `install_statusline`, `install_allowlist`, `install_metrics_tool` and `uninstall_stack`. Runtime entry is Claude Code firing the hooks registered in `.claude/settings.json`.
- `hooks/global/`: 7 soft nudge hooks (cmm-nudge, cmm-grep-nudge, cmm-orient-nudge, reindex-after-edit, subagent-ctx-startup, user-prompt-submit-skill-nudge, webfetch-nudge).
- `hooks/project/`: 21 per-repo blocking gates, trackers and sentinel writers (session-gate, grep-cmm-gate, agent-cmm-gate, index-root-gate, cwd-guard, ctx-* guards, track-*, reindex-after-commit, cmm-query.sh, agent-override-generate.sh).
- `hooks/lib/`: 5 shared sourced libs (`cmm-registered.sh`, `context-mode-detect.sh`, `is-cmm-ext.sh`, `project-root.sh`, `vbw-source.sh`).
- Other top-level dirs:
  - `rules/`: templates, `allowed-tools.txt`.
  - `agents/`: 7 `vbw-*.md`.
  - `skills/`: cmm-rules, ctx-rules.
  - `scripts/`: bump-version, generate-checksums, `analyze-*.py`, skill-compliance.
  - `tests/`: with `fixtures/` and `live/`.
  - `benchmarks/`, `docs/`.
- Runtime flow:
  - SessionStart runs `cmm-session-start.sh`.
  - PreToolUse `*` runs `session-gate.sh`, which blocks everything until the index is fresh. The sentinel is `/tmp/cmm-session-ready-<root-md5>`.
  - Tool-specific PreToolUse hooks:
    - `index_repository` runs `index-root-gate`.
    - `Agent` runs `agent-cmm-gate`.
    - `Bash` runs `ctx-execute-enforcer`, `cwd-guard` and `cmm-grep-nudge`. `# cmm-exempt` bypasses the last.
    - `Read` runs `cmm-nudge`.
    - `Grep` runs `grep-cmm-gate`.
    - `ctx_execute*` runs the ctx-* guards.
  - PostToolUse: `cmm-sentinel-writer` opens the gate, plus `reindex-after-commit`, the `track-*` counters and the advisory nudges.
  - SubagentStart injects guidance. UserPromptSubmit runs the skill nudge.
- `hooks/lib/cmm-registered.sh` `cmm_is_registered` probes `mcpServers.codebase-memory-mcp` the same way `setup.sh` does. `_cmm_config_dir` mirrors `detect_config_dir` in `setup.sh`, so change both together.
- Current branch `feature/102-vbw2-compatibility` is VBW 2 compatibility work. The touchpoints are `hooks/lib/vbw-source.sh`, `agents/vbw-*.md` and `.vbw/`. VBW is optional per `CLAUDE.md`.

## Conventions

- Hook header:
  - `#!/bin/bash`.
  - Line 2 is `name — event:matcher (purpose)`.
  - Comments mark BLOCKING or advisory, plus Install and Register snippets.
  - `# --- Section ---` dividers.
  - Read stdin with `INPUT=$(cat)`. Parse JSON with inline `python3 ... 2>/dev/null || echo ""`, so malformed input fails open.
  - No `set -e` in hooks. Exit 2 blocks, exit 0 allows.
- Shared logic goes in `hooks/lib` and is sourced, not inlined (`tests/test-hooks-use-shared-lib.sh` enforces this). Lib files carry a "WHY THIS EXISTS" header.
- Fail open unless CMM or Context Mode is truly registered. Use the detect helpers, not file-presence checks.
- Test files:
  - One `tests/test-<feature>.sh` per hook or feature (phase-numbered ones exist for installer bundles).
  - `set -euo pipefail`.
  - `SCRIPT_DIR` via `cd "$(dirname "${BASH_SOURCE[0]}")" && pwd -P`.
  - `_pass`/`_fail` helpers that print `PASS: x` or `FAIL: x`.
  - Throwaway repos via `mktemp -d /tmp/cmm-*-XXXXXX` plus `git init -q`.
- Git and process:
  - Commit as `{type}({scope}): {desc}`, one atomic commit per task.
  - No secrets. No push or version bump unless asked.
  - Flow is `feature/*` -> `develop` -> `main`, with a bump via `scripts/bump-version.sh` and a `vX.Y.Z` tag.
  - Never hand-edit `.vbw-planning/` or `.vbw/`.
- PR QA:
  - PRs touching `hooks/`, `setup.sh`, `rules/` or `agents/` need 2-4 rounds of read-only Opus QA in fresh sessions (`CONTRIBUTING.md § Pull Request Process`).
  - Fixes go in separate `fix(scope): address QA round N` commits, with no amend. Post each report as a PR comment.
  - Docs-only PRs skip this.
  - QA prompts that spawn agents must mention CMM tools, or `agent-cmm-gate.sh` blocks them.
  - VBW 2 alternative: `/qa-cycle <pr>`, then `vbw prove` and `vbw req accept <ID>`.
- No `.editorconfig` or formatter config. Style is convention only.

## Tests

- No framework (bats is installed but unused). `make test` (`Makefile`) loops over sorted `tests/test-*.sh`, prints PASS/FAIL per file and hides output. There is no CI.
- Layout: about 66-69 `tests/test-*.sh` files, plus `tests/setup-test-monorepo.sh` (shared helper), `tests/fixtures/{skill-compliance,vbw2-workflow}` and `tests/live/{vbw2-map-run.sh,vbw2-measure-live.sh}`. The live scripts are not in `make test`.
