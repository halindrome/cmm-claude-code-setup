# Phase 03 Research: Project Hooks

## Findings

### Hook Behavior Requirements

#### 1. **cmm-session-start.sh** (SessionStart)
- **Input**: None (SessionStart doesn't receive JSON input; generates prompt injection)
- **Output**: Text prompt that becomes system message injected before session
- **Behavior**: Delete stale sentinel on startup to force fresh index check. Output mandatory first-action block instructing Claude to run `index_status` then `index_repository`.
- **Exit Code**: Always 0
- **Sentinel Interaction**: Deletes `/tmp/cmm-session-ready-${PPID}` on startup

#### 2. **cmm-session-gate.sh** (PreToolUse:*)
- **Input**: JSON via stdin with `tool_name` field
- **Output**: Exit code only (or error message on block)
- **Behavior**:
  - Check for sentinel at `/tmp/cmm-session-ready-${PPID}`
  - If sentinel exists → exit 0 (allow all tools)
  - If sentinel missing → exit 2 to BLOCK with message
  - **Exception**: Always allow `mcp__codebase-memory-mcp__index_repository`, `mcp__codebase-memory-mcp__index_status`, and `ToolSearch` through regardless
- **Exit Codes**: 0 = allow, 2 = block

#### 3. **cmm-sentinel-writer.sh** (PostToolUse:mcp__codebase-memory-mcp__index_repository)
- **Input**: JSON via stdin with `tool_name` field
- **Output**: Advisory confirmation message to stdout
- **Behavior**: Write "ready" marker to `/tmp/cmm-session-ready-${PPID}`. Outputs confirmation.
- **Exit Code**: Always 0
- **Key**: Only triggered on `index_repository` completion (not all PostToolUse)

#### 4. **agent-cmm-gate.sh** (PreToolUse:Agent)
- **Input**: JSON via stdin with `prompt` and `subagent_type` fields
- **Output**: Exit code + error message with full copy-paste instructions on block
- **Behavior**:
  - Extract `prompt` from JSON
  - Search prompt for CMM keywords: `search_graph`, `trace_call_path`, `get_code_snippet`, `index_repository`, `detect_changes`, `get_architecture`, `query_graph`
  - If keywords found → exit 0 (allow)
  - If keywords missing → exit 2 + output FULL copy-paste MCP instructions
  - Exempt `claude-code-guide` subagent_type (pure help, no code access needed)
- **Exit Codes**: 0 = allow, 2 = block

#### 5. **track-cmm-calls.sh** (PostToolUse:mcp__codebase-memory-mcp__*)
- **Input**: JSON via stdin with `tool_name`
- **Output**: Silent
- **Behavior**: Parse tool_name from input, increment `by_tool[tool_name]` and `total_calls` in `~/.cache/codebase-memory-mcp/_call-counts.json`
- **Exit Code**: Always 0 (fail silently if write fails)
- **Atomicity**: Write to temp file + `mv` (atomic POSIX rename)

---

### Sentinel File Pattern

**Path**: `/tmp/cmm-session-ready-${PPID}`
- `PPID` = Claude Code parent process ID (stable for session lifetime, unique per session)
- **Format**: Single line "ready"
- **Lifecycle**: Deleted by session-start → written by sentinel-writer → read by session-gate
- **Cleanup**: OS cleans `/tmp` periodically; PPID changes on restart so no orphan conflicts

## Relevant Patterns

### Input Parsing by Hook Type

**SessionStart** (no input):
```bash
# Output text directly — becomes system prompt injection
cat <<'PROMPT'
**MANDATORY FIRST ACTION:**
1. Run index_status
2. If stale, run index_repository
PROMPT
```

**PreToolUse** (JSON input):
```bash
INPUT=$(cat)
TOOL=$(echo "$INPUT" | python3 -c "import sys,json; print(json.load(sys.stdin).get('tool_name',''))" 2>/dev/null)
PROMPT_TEXT=$(echo "$INPUT" | python3 -c "import sys,json; print(json.load(sys.stdin).get('prompt',''))" 2>/dev/null)
```

**PostToolUse** (JSON input):
```bash
INPUT=$(cat)
TOOL=$(echo "$INPUT" | python3 -c "import sys,json; print(json.load(sys.stdin).get('tool_name',''))" 2>/dev/null)
```

### Exit 2 Blocking Pattern

```bash
cat <<'BLOCK'
BLOCKED: [reason]. Do this first: [instructions]
BLOCK
exit 2
```

### CMM vs jmunch Differences

| Aspect | jmunch | CMM |
|--------|--------|-----|
| Indexes | Two (jCodeMunch + jDocMunch) | One (index_repository) |
| Sentinel | Two-line ("code"/"doc") | Single-line ("ready") |
| Token tracking | `tokens_saved` from response | Call counts only |
| Tool prefix | `mcp__jcodemunch__*` / `mcp__jdocmunch__*` | `mcp__codebase-memory-mcp__*` |

---

## Risks

1. **jq dependency**: `track-cmm-calls.sh` needs jq. Add python3 fallback or document as requirement.
2. **Agent gate false positives**: If prompt mentions keyword in passing, allowed through. Acceptable — explicit keyword = intent to use.
3. **Call tracker atomicity**: Use temp file + mv pattern (POSIX atomic). Acceptable for counting.
4. **Sentinel PPID orphans**: Old sentinels in /tmp won't conflict; new sessions get new PPID.

---

## Recommendations

1. **Sentinel path**: `/tmp/cmm-session-ready-${PPID}` — use literally in all three sentinel hooks
2. **Session gate**: Allow `mcp__codebase-memory-mcp__index_repository`, `mcp__codebase-memory-mcp__index_status`, `ToolSearch`
3. **Agent gate keywords**: `search_graph|trace_call_path|get_code_snippet|index_repository|detect_changes|get_architecture|query_graph`
4. **Call tracker path**: `~/.cache/codebase-memory-mcp/_call-counts.json` (matches README)
5. **Session-start prompt**: Must emphasize "MANDATORY FIRST ACTION" and "before responding to user"
6. **Error messages**: Include full copy-paste MCP instructions on block (agent gate especially)
7. **Silent failure**: track-cmm-calls.sh — never output, never block, always exit 0
8. **File headers**: Each hook needs Purpose, Install instructions, Matcher comment
