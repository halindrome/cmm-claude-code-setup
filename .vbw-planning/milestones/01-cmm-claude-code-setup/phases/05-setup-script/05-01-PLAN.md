# Plan 01: setup.sh — automated hook installer

## Output File
`setup.sh` (project root)

## Task 1: Write the complete setup.sh script

Create `setup.sh` at the project root. The script must be complete and executable. Below is the full specification for every section.

### 1.1 Header Comment Block

```bash
#!/usr/bin/env bash
set -euo pipefail

# setup.sh — Automated installer for codebase-memory-mcp Claude Code hooks
#
# Usage:
#   ./setup.sh [--global] [--project] [--all] [--force] [--dry-run]
#
# Flags:
#   --global     Install global hooks to ~/.claude/hooks/ and merge into ~/.claude/settings.json
#   --project    Install project hooks to .claude/hooks/, rules to .claude/rules/,
#                create .mcp.json, and merge into .claude/settings.json
#   --all        Install both global and project hooks
#   --force      Overwrite existing files (default: skip existing)
#   --dry-run    Show what would be done without making changes
#
# No flags: interactive prompt asking which to install.
#
# Prerequisites:
#   - python3 (required — used for JSON merging)
#   - codebase-memory-mcp (optional — warns if not found on PATH)
#
# Run from the repo root (the directory containing this script).
# chmod +x setup.sh before first run.
```

### 1.2 Constants and Globals

Define these at the top after the header:

```bash
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
FORCE=false
DRY_RUN=false
INSTALL_GLOBAL=false
INSTALL_PROJECT=false
```

### 1.3 Argument Parsing

Parse CLI args in a `while` loop over `"$@"`:

| Arg | Action |
|-----|--------|
| `--global` | `INSTALL_GLOBAL=true` |
| `--project` | `INSTALL_PROJECT=true` |
| `--all` | `INSTALL_GLOBAL=true; INSTALL_PROJECT=true` |
| `--force` | `FORCE=true` |
| `--dry-run` | `DRY_RUN=true` |
| `*` | Print "Unknown flag: $1" to stderr, exit 1 |

After parsing, if NEITHER `INSTALL_GLOBAL` nor `INSTALL_PROJECT` is true, call `interactive_prompt`.

### 1.4 interactive_prompt() Function

Print a question and read one character:

```
Which hooks would you like to install?
  g) Global hooks only (~/.claude/hooks/)
  p) Project hooks only (.claude/hooks/)
  a) Both global and project
  q) Quit

Choice [a]:
```

Default (empty input) = `a`. Map `g` -> INSTALL_GLOBAL=true, `p` -> INSTALL_PROJECT=true, `a` -> both true, `q` -> exit 0. Invalid input -> print error, re-prompt (loop).

### 1.5 Prerequisites Check: check_prerequisites()

1. **python3** (required): `command -v python3 >/dev/null 2>&1` — if missing, print error to stderr and `exit 1`.
2. **codebase-memory-mcp** (optional): `command -v codebase-memory-mcp >/dev/null 2>&1` — if missing, print warning: `"Warning: codebase-memory-mcp not found on PATH. Install it before using hooks."` Continue execution.
3. **Source directories**: Check `"$SCRIPT_DIR/hooks"` exists. If not, error + exit 1. If `INSTALL_PROJECT` is true, also check `"$SCRIPT_DIR/rules"` exists.

### 1.6 Utility Functions

#### copy_file(src, dest)
Handles copy with force/dry-run/skip logic:
- If `DRY_RUN=true`: print `"  [DRY RUN] Would copy $(basename "$src") -> $dest"` and return.
- If file exists at dest AND `FORCE != true`: print `"  [skip] $(basename "$dest") already exists (use --force to overwrite)"` and return.
- Otherwise: `cp "$src" "$dest"` and print `"  [ok] Copied $(basename "$dest")"`.

#### set_executable(file)
- If `DRY_RUN=true`: print `"  [DRY RUN] Would chmod +x $file"` and return.
- Otherwise: `chmod +x "$file"` (no output, folded into the copy step status).

**Step 3: Merge settings**

### 1.9 merge_settings_json() Function

**Signature:** `merge_settings_json(target_file, mode)`

Where `mode` is `"global"` or `"project"`.

**Dry-run check:** If `DRY_RUN=true`, print `"  [DRY RUN] Would merge hooks into $target_file"` and return.

**Backup:** If `target_file` exists, copy it to `"${target_file}.backup"` and print `"  [ok] Backed up $(basename "$target_file") -> $(basename "$target_file").backup"`.

**Ensure parent directory:** `mkdir -p "$(dirname "$target_file")"`.

**Determine new hooks JSON:**
- If `mode == "global"`: use this exact JSON string (hardcoded in the script as a heredoc):

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Read",
        "hooks": [{"type": "command", "command": "bash \"$HOME/.claude/hooks/cmm-nudge.sh\""}]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [{"type": "command", "command": "bash \"$HOME/.claude/hooks/reindex-after-edit.sh\""}]
      }
    ]
  }
}
```

IMPORTANT: The `$HOME` in the JSON must NOT be expanded by bash. Use a single-quoted heredoc (`<<'HOOKJSON'`) to prevent variable expansion.

- If `mode == "project"`: read the file `"$SCRIPT_DIR/rules/project-settings-example.json"`.

**Python3 merge logic:**

Call python3 with an inline script. Pass target_file and new_hooks_json as arguments. The python script must:

1. Read existing `target_file` (or use `{}` if not found / invalid JSON).
2. Parse `new_hooks_json` (passed as second arg or via stdin).
3. For each hook type key in `new_hooks["hooks"]` (e.g., `"SessionStart"`, `"PreToolUse"`, `"PostToolUse"`):
   - If that key doesn't exist in `existing["hooks"]`, create it as an empty list.
   - If `"hooks"` key doesn't exist in `existing`, create it as an empty dict.
   - Extend the existing list with the new entries (append, not replace).
4. Write to a temp file (`target_file + ".tmp"`).
5. Use `os.replace(tmp, target_file)` for atomic write.

Here is the exact python3 inline script to embed (pass as `python3 -c '...'`):

```python
import json, os, sys

target_file = sys.argv[1]
new_json_str = sys.argv[2]

# Read existing
try:
    with open(target_file, 'r') as f:
        existing = json.load(f)
except (FileNotFoundError, json.JSONDecodeError):
    existing = {}

# Parse new
new_data = json.loads(new_json_str)

# Deep merge hooks arrays
if 'hooks' not in existing:
    existing['hooks'] = {}
for hook_type, entries in new_data.get('hooks', {}).items():
    if hook_type not in existing['hooks']:
        existing['hooks'][hook_type] = []
    existing['hooks'][hook_type].extend(entries)

# Preserve any non-hooks keys in existing (e.g., permissions, allowedTools)

# Atomic write
tmp = target_file + '.tmp'
with open(tmp, 'w') as f:
    json.dump(existing, f, indent=2)
    f.write('\n')
os.replace(tmp, target_file)
```

**Post-merge validation:**

After the python3 merge, validate with:
```bash
python3 -m json.tool "$target_file" >/dev/null 2>&1
```
If exit code is 0: print `"  [ok] Merged hooks into $(basename "$target_file")"` then `"  [ok] JSON validated"`.
If exit code is non-zero: print `"  [ERROR] JSON validation failed for $target_file"` to stderr, exit 1.

### 1.11 main() Entry Point

```bash
main() {
    parse_args "$@"
    check_prerequisites

    if [ "$INSTALL_GLOBAL" = true ]; then
        install_global
    fi
```

### 1.12 Implementation Notes for Dev Agent

1. **The for-loop globs**: Use `for file in "$SCRIPT_DIR/hooks/global/"*.sh; do` — quote `$SCRIPT_DIR` but the glob `*.sh` must be outside quotes so it expands.
2. **The global hooks JSON heredoc**: Use `<<'HOOKJSON'` (single-quoted delimiter) to prevent `$HOME` expansion in the JSON. Capture into a variable: `GLOBAL_HOOKS_JSON=$(cat <<'HOOKJSON' ... HOOKJSON)`.
3. **The project hooks JSON**: Read from file: `PROJECT_HOOKS_JSON=$(cat "$SCRIPT_DIR/rules/project-settings-example.json")`.
4. **The python3 -c script**: Pass the JSON string as a command-line argument. Be careful with quoting — the JSON contains double quotes. Use single quotes around the python script, and pass the JSON via `sys.argv[2]`. The target file path is `sys.argv[1]`.
5. **Order of functions in the file**: Define all functions before `main()`. Order: utility functions (copy_file, set_executable), interactive_prompt, check_prerequisites, merge_settings_json, install_global, install_project, print_next_steps, main. Then call `main "$@"` as the last line.
6. **The script should be approximately 200 lines of bash.** Do not pad with excessive comments — keep it clean and functional.
7. **Do NOT use `jq` anywhere.** Python3 only for all JSON operations.
8. **set -euo pipefail** at the top — the script should fail fast on errors. However, the `command -v codebase-memory-mcp` check must use `|| true` or an if-statement to avoid triggering `set -e`.
