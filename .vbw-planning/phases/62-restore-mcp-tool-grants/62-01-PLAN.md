## Objective

Fix two related defects that prevent CMM and context-mode MCP tools from being callable by the four override agents
(`vbw-lead`, `vbw-debugger`, `vbw-docs`, `vbw-architect`), and fix `setup.sh`'s `permissions.allow` writer to emit
both the plugin-form and legacy context-mode tool names. These agents are installed by `setup.sh --project` to shadow
VBW plugin agents and inject CMM enforcement — they nag agents to use CMM tools those agents cannot call.

## Context

- `@agents/vbw-lead.md` — has `tools:` allowlist missing all `mcp__*` names; has scoped `Task(vbw-dev)` grant
- `@agents/vbw-debugger.md` — has `tools:` allowlist missing all `mcp__*` names; has scoped `Task(vbw-debugger)` grant
- `@agents/vbw-docs.md` — has `tools:` allowlist missing all `mcp__*` names; no scoped Task grant
- `@agents/vbw-architect.md` — has `tools:` allowlist missing all `mcp__*` names; no scoped Task grant
- `@setup.sh` — `permissions.allow` writer (~lines 2500-2536) emits only legacy `mcp__context-mode__*`; hook matchers
  (~lines 1340-1376) already handle both prefixes plugin-form-first (canonical pattern to follow)
- `@CHECKSUMS.sha256` — must be regenerated for any agent files changed
- `@.vbw-planning/phases/62-restore-mcp-tool-grants/62-RESEARCH.md` — complete verified findings (authoritative)

Design decisions:
- **vbw-lead / vbw-debugger**: keep `tools:` allowlist form (scoped Task grants cannot be expressed in a denylist);
  add all MCP tool names explicitly.
- **vbw-docs / vbw-architect**: convert to `disallowedTools: Task` denylist form. This is the VBW source convention
  (vbw-scout, vbw-dev, vbw-qa all use denylist) and avoids future MCP surface drift without re-editing these files.
  `Task` is the only tool that should be restricted for these agents (matches vbw-qa pattern from Phase 52).
- **Wildcard vs enumerate**: use explicit enumeration for all MCP tool names in `tools:` allowlists. Claude Code
  agent `tools:` wildcard support (e.g., `mcp__server__*`) is unverified; project convention is explicit enumeration
  (see `settings.json`, hook matchers).
- **Tool names to add** (CMM): `mcp__codebase-memory-mcp__get_architecture`, `mcp__codebase-memory-mcp__search_graph`,
  `mcp__codebase-memory-mcp__get_code_snippet`, `mcp__codebase-memory-mcp__trace_path`,
  `mcp__codebase-memory-mcp__query_graph`, `mcp__codebase-memory-mcp__search_code`,
  `mcp__codebase-memory-mcp__index_status`, `mcp__codebase-memory-mcp__index_repository`
- **Tool names to add** (context-mode plugin form): `mcp__plugin_context-mode_context-mode__ctx_execute`,
  `mcp__plugin_context-mode_context-mode__ctx_execute_file`, `mcp__plugin_context-mode_context-mode__ctx_search`,
  `mcp__plugin_context-mode_context-mode__ctx_batch_execute`, `mcp__plugin_context-mode_context-mode__ctx_index`,
  `mcp__plugin_context-mode_context-mode__ctx_fetch_and_index`, `mcp__plugin_context-mode_context-mode__ctx_stats`
- **Tool names to add** (context-mode legacy form): `mcp__context-mode__ctx_execute`,
  `mcp__context-mode__ctx_execute_file`, `mcp__context-mode__ctx_search`, `mcp__context-mode__ctx_batch_execute`,
  `mcp__context-mode__ctx_index`, `mcp__context-mode__ctx_fetch_and_index`, `mcp__context-mode__ctx_stats`
- **Excluded**: `mcp__codebase-memory-mcp__delete_project` (destructive); `mcp__*__ctx_doctor`,
  `mcp__*__ctx_upgrade`, `mcp__*__ctx_purge` (operator-only); stale `trace_call_path` (non-existent tool)
