## Objective
Extract the duplicated 20-line git superproject traversal + worktree detection + PROJECT_HASH computation into a shared library at `hooks/lib/project-root.sh` with persistent `/tmp` caching. Update `setup.sh` to install the lib directory for project installs. This is the foundation for Plan 04 which migrates all hooks to source this library. (REC-05, REC-02)

## Tasks

### Task 1: Create hooks/lib/project-root.sh
**Commit:** `feat(hooks): extract shared project-root detection library with /tmp cache`

Create `hooks/lib/project-root.sh` that:
1. Checks for cached values first: reads `/tmp/cmm-project-root-$(echo -n "$(pwd)" | md5 -q 2>/dev/null || echo -n "$(pwd)" | md5sum | cut -d' ' -f1)`. Cache file format: line 1 = PROJECT_ROOT, line 2 = PROJECT_HASH.
2. If cache hit and the directory still exists (`[ -d "$PROJECT_ROOT" ]`), uses cached values.
3. If cache miss or stale, runs the full git superproject chain walk + worktree detection (copy verbatim from session-gate.sh lines 15-60), computes PROJECT_HASH via `md5`, writes cache file.
4. Exports: `PROJECT_ROOT`, `PROJECT_HASH`, `CMM_SENTINEL="/tmp/cmm-session-ready-${PROJECT_HASH}"`, `CTX_SENTINEL="/tmp/cmm-ctx-ready-${PROJECT_HASH}"`.
5. Make executable with `chmod +x`.

Key design points:
- Idempotent: safe to source multiple times (guard with `[ -n "$_PROJECT_ROOT_LOADED" ] && return 0`).
- Cache key is md5 of `$(pwd)`, so different directories get different caches.
- Fallback: if `git rev-parse` fails entirely, use BASH_SOURCE dirname traversal (same as current hooks).

### Task 2: Update setup.sh to install hooks/lib/ for project installs
**Commit:** `feat(setup): install hooks/lib/ directory for project hook installs`

In `install_project()` function (around line 762), add:
1. `mkdir -p .claude/hooks/lib` (after the existing `mkdir -p .claude/hooks`).
2. Copy loop for `hooks/lib/*.sh` files (same pattern as global install at lines 727-731):
   ```bash
   for file in "$SCRIPT_DIR/hooks/lib/"*.sh; do
     copy_file "$file" ".claude/hooks/lib/$(basename "$file")"
   done
   ```
3. Add pre-scan drift detection for `.claude/hooks/lib` (same as line 768 pattern).
4. In the cache invalidation section (during `--project` install), delete stale `/tmp/cmm-project-root-*` files for the current directory's hash to force re-detection after reinstall.

### Task 3: Add integration test for project-root library
**Commit:** `test(hooks): verify project-root library caching and export behavior`

Create `tests/test-project-root-lib.sh` that:
1. Sources `hooks/lib/project-root.sh` from a git repo context.
2. Verifies PROJECT_ROOT, PROJECT_HASH, CMM_SENTINEL, CTX_SENTINEL are all set.
3. Verifies cache file exists at expected `/tmp/cmm-project-root-<hash>` path. Note: the hash is computed from `$(pwd)` (not `$(pwd -P)`), matching the library's actual behavior. On macOS, `/var/folders` is a symlink, so `pwd` and `pwd -P` produce different values; the library intentionally uses `pwd` for consistency with how hooks are invoked.
4. Sources again and verifies the fast path is taken (cache hit -- could verify by checking that `_PROJECT_ROOT_LOADED` is already set).
5. Removes cache file, sources again, verifies it re-creates the cache.
6. Tests fallback: run in a non-git directory, verify PROJECT_ROOT falls back to BASH_SOURCE resolution.

## Amendments

**[R01-DEV-01] md5 flag correction (Task 1):** Changed `md5 -qs` to piped `echo -n | md5 -q`. The `-qs` flag combination fails on piped input on macOS because `-s` treats the next argument as a literal string, not stdin. The correct approach pipes input to `md5 -q` which reads from stdin and outputs only the hash.

**[R01-DEV-02] pwd vs pwd -P clarification (Task 3):** Clarified that the test and library use `$(pwd)` (not `$(pwd -P)`) for cache key computation. On macOS, `/var/folders` is a symlink, so `pwd` and `pwd -P` return different paths. The library intentionally uses `pwd` to match how hooks are invoked by Claude Code, ensuring cache keys are consistent across all hook calls in a session.
